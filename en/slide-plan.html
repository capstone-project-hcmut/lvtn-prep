Problem recap

1:30 · slides 4-5
4

High demand, high cost

  • An IELTS score of 4.0 or above exempts students from the national exam and counts as 10 points for the foreign language subject in high school graduation; more than 100 universities use IELTS in admissions; high school students now make up 30% of test takers
  • Vietnamese test takers are weakest in Writing (6.0) and Speaking (5.7). This is why AI grading of these two skills is the focus of Reeldemy.
  • Language centers charge 60-100 million VND to raise a score from 5.5 to 7.5, pushing learners toward unguided online self-study
Source: Chapter 1, Context
5

Existing platforms vs. Reeldemy

  • One comparison table: Prep.vn, DOL English, IELTS Online Tests, Reeldemy
  • Criteria: next-lesson recommendation based on competency · coverage of all question types · AI grading of Writing and Speaking · cost per AI grading (IOT charges $9.99)
Source: Chapter 1, Existing System and Problem Statement. Replaces phase 1 slides 5-9.

Deep dive 1: adaptive mechanism

2:30 · slides 10-11
10

How the daily plan is chosen

PS = Wdecay · DecayFactor + Wrel · RelevanceScore
  • DecayFactor: Σ weight × (1 − FSRS retrievability) over the exercise's competencies. Skills the learner is forgetting rank higher.
  • Relevance (as implemented): 0.5 × (this skill's gap to target ÷ the largest gap among skills) + 0.5 × Σ weight × (1 − competency score)
  • Wdecay = 0.5 when streak ≤ 3, and 0.2 when streak > 3

Worked example (illustrative numbers; replace with a real score breakdown taken from the API):

Candidate exerciseDecayRSskillRScompRSPS (streak ≤ 3)PS (streak > 3)
A: Writing Task 2 (score 0.55, R = 0.90)0.101.000.450.7250.4130.600
B: Reading (score 0.70, R = 0.40)0.600.250.300.2750.4380.340
How to say it: "A new learner is sent back to the Reading material they are forgetting. Once a study habit forms, the plan shifts toward the skill furthest from the target, which is Writing." This example shows numerically that the system aims at the goal without neglecting any skill.
Code: reeldemy-be/src/modules/exercise/recommendation.service.ts, constants in src/common/constants/competencies.constants.ts. The API response already includes the breakdown fields (ps, decayFactor, rs, rsSkill, rsComp).

Deep dive 2: full range of exercise types

2:30 · slides 12-13
12

Practice close to the real exam for all four skills

  • Reading: split-screen passage view, 14 question group types (matching, True/False/Not Given, sentence completion, diagram labeling, etc.)
  • Listening: audio per part, the same question types as Reading, with note-taking and volume control
  • Writing: Task 1 with a chart and Task 2, live word count, 10,000 character limit
  • Speaking: 3 parts (introduction, long turn with a cue card, discussion), recording flow: microphone permission → preparation → speaking → playback
  • How it works: a QuestionGroup component routes each question group to one of a few shared renderers, so the 28 Reading and Listening question types do not need 28 separate screens
  • Shared across all skills: warnings at 5 minutes and 1 minute remaining, auto-submit at time out, autosave (in the browser and to the server every 10 seconds), resuming an unfinished session

Deep dive 3: AI grading

4:30 · slides 14-17
14

The Writing grading pipeline

  • Submit → session moves to GRADING → BullMQ job → DeepSeek → JSON validated against a schema → saved → the result screen polls every 2 seconds
  • Prompt layers: hardened system prompt, rubric (4 criteria scored against band descriptors), the task prompt, the server-counted word count against the minimum (150/250), and the admin's grading notes
  • Invalid output is retried up to 3 times with backoff; if it still fails, the session is marked as failed and the error is reported
Source: Chapter 5, Grading and Competency Update
15

The Speaking pipeline & live AI examiner

  • MediaRecorder → upload to R2 via presigned URL → gpt-4o-transcribe → DeepSeek grades, one score per Part
  • Pronunciation is deliberately not graded: a transcript cannot represent pronunciation
  • Live examiner for Part 1 and Part 3: WebRTC, short-lived token, examiner instructions set on the server
  • Grading is based on the recorded file. If the live connection drops, the learner loses only the conversation, not the graded submission.
Show the frontend fallback message ("We'll record your answers instead").
16

Can the AI's grading be trusted?

  • Five failure modes and their controls: malformed output → schema validation and retry · wrong length counting → word count computed in code · prompt injection → the essay is treated as untrusted content, with length and language checks · learners seeing grading notes → notes are stripped from the payload sent down · overtrusting the band → shown as an "estimated practice score"
  • A validation protocol with targets fixed in advance: MAE ≤ 1.0 band · agreement within 0.5 band ≥ 60% · QWK ≥ 0.60 · ≥ 80% of essays varying by at most 0.5 band across 5 gradings · attack success rate ≤ 10%
  • If the team has run the experiment, put the results here.
Source: Chapter 5, Validation of AI Grading

Deployment

1:00 · slide 20
20

How the system is deployed and operated

  • Infrastructure diagram: frontend on Cloudflare Pages · backend as a Docker container on Google Compute Engine · MongoDB Atlas · Redis on the same VM · Cloudflare R2 + CDN
  • CI/CD pipeline (GitHub Actions): lint & type-check → unit + integration tests → build & push image to GitHub Container Registry → deploy over SSH. End-to-end tests (Playwright) run against each PR's preview build.
  • 4 environments: local · per-PR preview · develop (develop branch) · production (main branch). Develop and production share no database, bucket or VM; secrets are separated through GitHub Environments.
  • Safe operation: multi-stage Docker image (node:20-alpine, runs as a non-root user) · environment variables validated with Joi at startup · a GET /health endpoint that checks both MongoDB and Redis, used for health checks and uptime monitoring
