1. Questions to prepare

High risk

High"How accurate is the AI grading? How do you know the band it gives is right?"
Why it is risky
The report sets up a validation protocol but has no results yet ("the corpus is still being assembled"). Yet this is the platform's main selling point.
Suggested answer
The band is clearly labeled as an estimated practice score, not an official result. Reading and Listening do not use AI. Writing and Speaking are constrained by a rubric based on band descriptors, the JSON output is schema-validated, the word count is computed by the server, and there is a retry mechanism. Accuracy is measured against real examiners, with targets fixed in advance (MAE ≤ 1.0, QWK ≥ 0.60). Prior work (Koraishi 2024) shows ChatGPT generally agrees highly with human examiners, though with some deviations.
Evidence
Chapter 5, Validation of AI Grading; the ai-controls and ai-targets tables
To prepare
Run an experiment before the defense, for example grade about 40 published Cambridge sample Task 2 essays once: MAE, agreement within 0.5 band, bias. One real number is worth far more than a protocol alone.
High"Is the recommendation algorithm in Chapter 3 really what is running?"
Why it is risky
Some parts of the design are not running yet: exercise difficulty and retrievability in the update formula, the growth of α, the number of exercises N, streak-based weighting, and the FR-6.2 fallback.
Suggested answer
Scoring and ranking are really running: an FSRS-based decay component plus a relevance component, with the plan stored once per day. The competency update is a simplified moving average (α = 0.7). The missing parts are waiting on data not yet collected: exercise difficulty, average daily study time, and the stored streak. Jump to backup slide B19 (design vs. implemented table).
Evidence
The "Current implementation status" notes in Chapter 3; Chapter 5, Grading and Competency Update
High"The relevance formula in the report does not match the code."
Why it is risky
Formula in the report: RS = Σ wc · max(0, (Targetc − Currentc) / 9). In the code: RS = 0.5 · (the skill's gap to target ÷ the largest gap) + 0.5 · Σ w · (1 − competency score). The target is set per skill, not per competency, and the report's status notes do not mention this difference.
Suggested answer
The implementation combines a skill-level gap to target with a competency-level weakness, because learners set their targets per skill when they start.
To prepare
Fix the relevance formula in RecommendationAlgorithm.tex to match the code, or add a status note explaining the difference. Use the code-based version on slide 10.
High"How much does each AI grading cost?"
Why it is risky
The team pitches a "low-cost AI loop" against IOT's $9.99 per grading, but the report gives no cost per grading.
To prepare
Estimate the tokens per Writing grading (prompt + essay + returned JSON) × the DeepSeek price; the per-minute cost of gpt-4o-transcribe for each Speaking Part; the per-minute cost of gpt-realtime for the live examiner. Put the numbers on backup slide B18.

Medium risk

Medium"Where is the Cache in the architecture actually used?"
Why it is risky
The architecture diagram has a Cache component, but in the backend Redis is used only by BullMQ (and pinged by the health check). There is no application-level cache.
Suggested answer / preparation
Either remove the Cache box from the diagram before the defense, or answer that Redis currently serves as the message broker for the queue and query caching is planned. On the client side, TanStack Query already caches server data.
Medium"Is the worker really a separate service? What happens when you scale to multiple instances?"
Suggested answer
Currently the consumers run in the same process as the API. The queue already decouples the job producer from the job processor, so they can be split into a separate service without changing the producer side. Known limitation: Redis is fixed at localhost:6379, so each VM has its own queue. This configuration must be moved to environment variables before running multiple instances or moving to Memorystore.
Evidence
Chapter 3, architecture (Worker section); Chapter 5, Known Limitations
Medium"Why MongoDB? And how is the competency update kept consistent, with no partial writes (NFR-3.5)?"
Suggested answer
MongoDB suits polymorphic exercise documents with deeply nested question groups, stored through MikroORM's discriminator inheritance. On consistency: the backend code uses no explicit transactions. The likely answer is that the profile lives in a single document, and MongoDB writes a single document atomically.
To prepare
Confirm the single-document write path in competency-calculator.service.ts, and how the failure-simulation test was run.
Medium"If Pronunciation is not graded, is the Speaking band still meaningful?"
Suggested answer
This is a deliberate choice: converting speech to text loses pronunciation information, so the system does not grade what it cannot observe rather than guess. Fluency is assessed only from what shows in the transcript, and the returned feedback states this limitation. The overall band is the mean of the three remaining criteria. Future work: assess pronunciation directly from audio with a dedicated model.
Medium"Can learners cheat with prompt injection?"
Suggested answer
The essay is sent only as untrusted user content, with an instruction never to follow requests found inside it. Submissions are capped at 10,000 characters and checked for minimum length, language and repetition before the model is called. Grading notes are stripped from the task sent to learners. The validation protocol includes about 80 attack essays, with a target of at most 10% success rate per category.
Medium"Are the load test numbers realistic?"
Suggested answer
The load test machine and the VM are on different continents, so about 220 ms of fixed network latency was subtracted from every measurement. The target is the shared develop VM, not a production-grade machine. Both conditions are documented along with the k6 script. Results: detail page p95 ≈ 280 ms; 10 users for 10 minutes stayed within the error threshold; the 100-user stress test returned 200 for every request.
To prepare
Have the k6 result screenshots ready.
Medium"What if the VM goes down or a new deployment breaks? Is there a rollback?"
Why it is risky
The backend runs on a single VM per environment, and images are tagged by branch name (:production, :develop) rather than by version, so the report does not describe how to return to the previous version.
Suggested answer
The container runs with --restart unless-stopped and has a health check, so it restarts on its own when the process fails. Every change must pass lint, tests and build before deploy, and is tried on the develop environment before production. The database is on MongoDB Atlas, with automatic backups, independent of the VM. Known limitation: there is no multi-instance setup or load balancing yet, and Redis is fixed at localhost.
To prepare
Confirm how the team would actually roll back (for example re-run the workflow on the previous commit, or add a commit-SHA tag to images).

Low risk

Low"Why service-based rather than monolith or microservices?"
Suggested answer
This architecture separates grading, competency and exercise logic clearly without the cost of microservices (a database per service, service discovery), which a team of 3 should not take on. The components can still be scaled separately later.
Low"Where does the exercise content come from? How many exercises are there? What about copyright?"
To prepare
Know the number of exercises per skill on production, the source of the reading passages and audio, and how the seeder is used. For the AI validation dataset, the report cites Cambridge sample essays by book, test and page instead of reproducing them.
Low"Who were the participants in the usability testing (NFR-6.1)?"
To prepare
Have ready the number of participants, their characteristics, how the sessions were run, and the completion times.
Low"How are an exercise's competency weights assigned? Who decides?"
Suggested answer
The admin assigns weighted competencies when creating an exercise, and the weights must sum to 1 (FR-3.1). The competency catalog is seeded, not created in the UI. Know how many competencies are seeded per skill and how they relate to the 44 IELTS question types.
Low"How do you protect the OpenAI key when using the live examiner?"
Suggested answer
The backend issues a short-lived client token; the real key stays on the server. The examiner instructions are sent in the token-creation request on the server, so they cannot be edited from browser devtools. Turn-taking uses the provider's voice-activity detection with a 700 ms silence threshold.
Low"Why use two AI providers?"
Suggested answer
DeepSeek is cheap for high-volume text grading, but has no audio or realtime endpoint. OpenAI handles speech-to-text and live voice conversation. Keeping them separate means changing the grading provider does not affect the Speaking flow. DeepSeek is called through an OpenAI-compatible client, so switching providers is easy.
Low"How is Reeldemy different from Prep.vn or DOL?"
Suggested answer
A daily plan based on what the learner is forgetting and the gap to their target, not a fixed roadmap (Prep) or leaving learners to find exercises themselves (DOL). Every question type across all four skills, not only multiple choice. AI grading of Writing and Speaking with no per-grading fee (IOT charges $9.99).
